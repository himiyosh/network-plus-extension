# Changelog

All notable changes to Network+ for DevTools. Versions follow [Semantic Versioning](https://semver.org/); `version` is bumped once per release rather than per commit. Published builds are listed under [GitHub Releases](https://github.com/himiyosh/network-plus-extension/releases).

## Unreleased

- Both store dossiers now record the `v1.12.0` release as observed rather than pending: the asset was re-downloaded from GitHub, matched against the pinned SHA-256, and byte-compared against a fresh local build. That comparison also settled a reproducibility claim the dossiers had been making too broadly. The archive normalizes its entry timestamps to the ZIP epoch in local time rather than UTC, so `npm run extension:package` reproduces the released bytes only under `TZ=UTC` — all eleven entry CRCs match from any timezone, but a JST build writes `01-01-1980 09:00` where CI writes `00:00`, and the archive lands on a different digest at the same 206937 bytes. CI runs in UTC, so the digest gate has always held there; the cost fell on an operator verifying a release on their own machine, who would see a mismatch with nothing in either dossier to explain it. Both now name the `TZ=UTC` requirement where they describe the rebuild.

- `store:pages` now finds this repository's own store identifiers without being told. It read `CHROME_ITEM_ID` and `EDGE_PRODUCT_ID` only from the environment or a local `.env`, which are not present in a fresh checkout, so the first run of a release tool failed on setup rather than doing its job. The two values now sit in the script as fallbacks, after the environment and the `.env`, so a second product can still be driven without editing it. They are identifiers, not credentials — neither does anything without an API key, the Chrome one appears verbatim in the public listing URL, and the project already records both for exactly this reason. Treating them as secrets bought no safety and cost a working first run.

## v1.12.0 - 2026-08-26

- Listing images are no longer swapped by hand. `npm run store:pages` drives both store consoles from the operator's machine — `login` once, then `chrome` and `edge` — clearing the slots it is replacing and uploading the current contents of `docs/store-assets/`. Package submission was already automated; the images were the one manual step left, because the Chrome Items API and the Edge Update API both take packages and nothing else. The file list is read from `inventory.json`, so a re-capture that renames a file cannot leave the script uploading the previous set; the store icon is never touched; and nothing is submitted — both consoles keep the result as a draft, so a mistake here cannot reach a public listing on its own. It runs on a Chrome profile of its own holding nothing but the two store logins, because Chrome 136 and later refuse remote debugging on the default profile and pointing a debugger at a copy of the real one would put every cookie the browser holds behind an open port. The approach is carried over from the sibling `dual-subtitles` project, which solved the same problem first.
- Right-clicking a `Path` or `URL` cell built its quick filter from the whole value, query string included. A query string is per-request state — session ids, cache busters, consent blobs, timestamps — so `Exclude Path /vevent?an_audit=0&referrer=…&ft=3` matched that one request and nothing else, which is the opposite of what excluding noise asks for; the rule is now built from the path without its query. The same entry printed the value in full, and an ad-tech path past 1,300 characters wrapped the context menu across the whole viewport: menu labels now shorten at 48 characters with the entire value kept in the tooltip and in the rule itself, no entry may wrap onto a second line, and the menu is bounded at 420px. That bound needed a second fix to hold — the popup clamp wrote the viewport width into an inline `max-width`, and an inline style outranks the sheet, so a popup's own cap was being undone every time it opened.
- The row menu's `Copy full request...` no longer opens a dialog. It was a modal that both picked the format and took the confirmation, and the picker was the part people came for, so the eight formats it offered (request summary, URL, cURL, fetch, PowerShell, Markdown, raw request, request body) now sit in the menu itself, collapsed behind one entry labelled `Copy full (unsanitized)`. The menu keeps the height it had, reaching a format costs one click instead of a dialog round trip, and the label names what it hands out at the point of choosing rather than after. Full HAR export and the full body copies in the Request and Response panes keep their warning and one-time confirmation; the READMEs, privacy note, architecture note, and both store dossiers were corrected together, since they stated that every full output sat behind a confirmation.
- Fixed the export-safety dialog showing its three export buttons in every mode. `choices.hidden` was being set for each non-export mode, but `.data-safety-choices{display:grid}` had no `[hidden]` companion rule and `display` outranks the UA hidden rule — the same trap that once left "hidden" toolbar buttons painted. A per-action copy confirmation was therefore also offering `Export sanitized HAR` and `Export sanitized CSV`, which is not what it was confirming.
- A binary response no longer arrives as mojibake with an empty Preview. Every cached body was pushed through `TextDecoder`, which substitutes U+FFFD for bytes it cannot interpret, so a GIF reached the Body and Raw panes as `GIF89a` followed by replacement characters and raw control bytes. Bodies whose decode came back that way are now shown as a `hexdump -C`-style dump — offset, hex, and the printable gutter that makes magic numbers and embedded strings legible — under a line naming the type, the byte count, and how much of the body the dump covers when it hits the 4 KB cap. The judgement reads the decoded bytes rather than the declared MIME type, because a network panel meets `x-unknown` and `application/octet-stream` constantly, meets images served under text types, and meets `image/svg+xml`, which is under `image/` and genuinely is text; a single stray bad byte in an otherwise readable page still renders as the page. Only a base64 body claims a dump, since that is the only case where the real bytes are held.
- The response Preview now paints a tracking pixel instead of an invisible dot. The image was rendered at its intrinsic size, so the 1x1 transparent GIF that cookie-sync endpoints return drew one transparent pixel and the pane read as broken — the reported "Preview doesn't show" was the image being there and being unseeable. Images now sit on a transparency checkerboard, one too small to see is enlarged with the factor named in the caption beside its real dimensions and byte size, and the enlargement is bounded by the box as well as by visibility so a 400x1 spacer is not asked to render 19,200 pixels wide. The preview also decides from the `Content-Type` header rather than the recorded HAR type, which is what finally previews rows whose type arrived as `x-unknown`.
- A row that matched several search keywords could only ever wear the first one’s tint, so "which of my keywords did this hit?" had no answer on the grid. Matched keywords now show as one chip per keyword, each in that keyword’s own colour, in a new Match column beside ID. The chips already existed but were rendered screen-reader-only, on the reasoning that the row tint was enough and inline badges crowded the ID column — the first half of that stopped holding as soon as two keywords matched, and the second is why they have their own column rather than riding inside the ID cell, which pushed the ID sideways as rows matched more. Three chips are shown and any beyond that collapse into a "+N" chip, with the full list kept in each chip’s accessible label. A column the reader has never seen is now inserted at its designed position rather than appended to the right-hand end of their saved order.
- The row context menu's isolate and exclude pair now follows the column you right-clicked, instead of always filtering by domain. Right-click a Method cell and it offers `Only Method POST` and `Exclude Method POST`; a Status cell offers the status, a Path cell the path, and so on for every filterable column. Both write the same `multiText` rules the Filters popup and the domain summary strip already share, so a rule made this way shows, counts and clears there too, an isolate still replaces an earlier isolate while excludes accumulate, and the domain pair remains as the fallback when the menu is opened by keyboard or on a column with nothing to filter on. The column is read from a `data-col-id` now written on every cell rather than counted by position, because a positional guess breaks the moment a column is hidden or reordered — which is when this is most likely to be used.
- Fixed three things that landed in the wrong place. The request details header prefixed the response status, so the request line people copy out of the panel arrived as `200 GET https://…`; the status already has its own grid column and heads the Response tab, so the header now states the request line alone. Pressing Auto-scroll only flipped a flag — nothing moved until the next request arrived, and after scrolling up nothing moved at all — so enabling it now jumps to the newest row, which is what pressing it asks for. And a row or a search hit scrolled into view came to rest underneath the sticky furniture: `scrollIntoView` stops as soon as the target is inside the scrollport, which counts the strip a sticky element sits on top of, so a grid row settled 29 pixels under the column header and a pane hit under the pane's own search bar. Both scrollports are now inset by the measured height of what covers them, which puts the row one pixel clear of the header instead of 29 under it.
- Japanese prose in the dialogs no longer breaks mid-word. The rule that governs it was `overflow-wrap:anywhere`, which offers a line break at every character, so a Japanese paragraph split ブラ|ウザ, プラッ|トフォーム and 知るこ|とも. Dialog prose now breaks by phrase (`word-break:auto-phrase`) and keeps `overflow-wrap:break-word` only as the emergency valve for a token too long for its line, and the support dialog widened to 600px, which stopped the two payment-route hints wrapping at all. Phrase-aware breaking analyses text in the document's language, which the panel never declared: the language chosen in Settings is now published on the document element, which also stops a screen reader announcing Japanese prose in an English voice. The support dialog also balances its lines, and its Japanese opening line was tightened to fit the measure: it ran 621px against 566px of column, wrapping to 55 characters and then 「なります。」 alone on a five-character second line, and now reads on one line with 45px to spare — enough that a wider font on another platform still lands on two balanced lines rather than an orphan. Contract tests pin the wrapping rules.
- Gave the support otter readable eyes. The face is composited from the toolbar badge, whose otter is asleep — its eye is a single-pixel dark bar, which at 6x reads as a dash rather than an eye. Two solid 2x2 squares read as calm round eyes instead. A catchlight was tried and rejected at both 2x2 and 2x3: one white pixel out of four or six leaves the dark remainder wedge-shaped, tilting the eye and making the face look angry.
- Redrew the optional support dialog's illustration as pixel art, in the toolbar mark's own language. It composites that mark's 22x15 face pixel-for-pixel beside a cream mug at 6x rather than redrawing the animal: every freehand attempt, smooth-vector and pixel alike, drifted into a round-headed, big-eared silhouette that reads as a bear cub, because the otter proportions the shipped mark already solves — wide short skull, tiny ears, a pale muzzle across the lower half — are easy to lose and hard to rediscover. The old hero had exactly that problem, and stood beside an accent-colored mug it had no relationship to. Steam, hearts and sparkles are single pixels stepping in whole cells, because a smooth curve or a fractional translate beside a scaled grid reads as a second, different drawing, and hovering either call to action sends the hearts up early so the reward for reaching toward the button arrives before the click. Every animation is listed in the reduced-motion block, and the ones that animate up from `opacity:0` restore a visible resting value there so stilling them cannot erase them.
- Rebalanced the same dialog away from prose. A four-line opening paragraph became one line plus three scannable chips (every feature free; no ads, telemetry, or account; optional, no perks), which is where the eye now lands before the two buttons. The commitments the project pins by contract — that contributing never unlocks, limits, or changes any feature, that payment happens on the external site and never inside DevTools, and that Network+ transmits no captured traffic or usage data and cannot tell whether you contributed — stay stated in full in the fine print rather than being summarized away.
- Fixed a display defect that made local resources look like network traffic. `data:` and `blob:` URLs parse cleanly but carry no host, and their entire payload lands in the URL object's pathname with the scheme dropped — so `blob:https://cdn.example/uuid` rendered with a blank Domain and a Path reading `https://cdn.example/uuid`, naming an origin the browser never contacted, and a `data:` image rendered as `image/svg+xml;base64,…`. The Domain column now names the scheme (`blob:`, `data:`, `about:`) for host-less URLs, which also gives the domain summary and the domain filters something to group on, so these rows can finally be isolated or excluded like any other domain. Three further places split the same way and are corrected too: the Raw request view rebuilt a request line from the scheme-stripped fragment, the comparison panel's column header did the same, and the resend dialog's target description concatenated `origin` onto `pathname` — which for `blob:` printed the inner URL twice and for `data:` prefixed the literal string `null`. Genuinely unparseable URLs still fall back to a blank domain and the raw string.
- Request retention is now unlimited out of the box. A long triage session no longer silently drops the request you were about to look for; the Settings dialog still states that memory can grow without bound, and turning Unlimited off restores a cap anywhere from 100 to 100,000 requests. Response bodies are unaffected — the 1 MiB per-body and 32 MiB shared-cache limits still apply, so the growth is row metadata rather than payloads. A saved retention choice is preserved; only a panel that never had one picks up the new default.
- Every dialog now shows its item names in Japanese when the language is 日本語, not just its explanatory prose. Settings, Export network data, Edit and resend request, Keyboard Shortcuts (including all seventeen action descriptions), the sample evidence guide, the undock explainer, and the support dialog were carrying English labels next to Japanese help text; 52 strings now switch with the language. Toolbar buttons and column headers deliberately stay in English so a written instruction still names the control you click and exports keep their English column names. Labels that wrap a checkbox or radio translate an inner span, never the label element, so applying a translation cannot replace the input — a contract test now enforces both that rule and that every tagged key has an en and a ja string.
- Both READMEs now link to the published Microsoft Edge Add-ons and Chrome Web Store listings: store badges in the header, store routes on the quick-try line, and a store-first section at the top of the quick start. The same pass corrected a claim that had gone stale — both files still stated that Network+ was "not yet published" on either store — and reframed the unpacked install as what it now is: the route for trying a build before it reaches the stores, or for pinning one exact version, without the automatic updates a store install gets. The browser-support table cites the listings instead of describing the submission dossiers as merely prepared.
- The mirror tab's undock explainer no longer wraps its instructions into a wall of short lines. The dialog was pinned to a fixed 440px while its own text needed roughly 800px, so five of its seven Japanese lines wrapped mid-sentence; it now sizes itself to its content (capped at 960px or the window width, whichever is smaller) and reads one sentence per line in both languages. Because the width is derived from the text rather than a hand-picked number, it stays correct across the two languages, the reader's font metrics, and any future wording change. A real-browser regression test measures the rendered line boxes in English and Japanese so a reflow cannot creep back.
- Added an optional per-domain summary: `Show domain summary` in the Columns menu reveals a collapsible strip above the grid listing each domain's request count, transferred bytes, and 4xx/5xx error count, ordered by traffic and updating live as requests stream in (a signature compare skips the rebuild when nothing changed, so it never churns focus or scroll). Clicking a domain shows only its requests and clicking again clears it — both write the same `multiText` domain rules the Filters popup and the row context menu already share, so applied filters show, count, and clear there too; requests without a parseable host appear as an informational `(no host)` entry. The strip is a sibling element above the workbench, never rows inside the grid, so the incremental streaming fast path and every flat-table behavior (keyboard navigation, striping, selection) are untouched, and it works identically in the pop-out mirror tab. The visibility choice persists per page. Grouped rows inside the table itself were deliberately deferred: a design survey with adversarial review confirmed they would conflict with ten independently pinned grid invariants, so this summary-first version ships the same triage value at a fraction of the risk.
- Japanese support now covers every explanatory surface, not just the settings and undock dialogs: the export-safety consent screen's warning prose, the resend dialog's intro and browser-managed-headers hint, the support and sample-guide dialogs, the safe-support-summary help, the empty-state titles and descriptions, the timing-phase guide and its evidence-limitation note, and the fixed body-unavailability notices all translate through the same `UI_TEXT` dictionary. Static tooltips translate through a new `data-i18n-title` attribute (dynamic, JS-composed titles deliberately keep their English text), strings the panel composes in JavaScript resolve through a `uiText(key)` lookup, and the already-rendered empty state re-renders in place when the language changes. Body-unavailability reasons stay canonical English on the row itself — they cross the mirror port and land in exports — and translate only where they are rendered. The completeness contract test now also verifies every `data-i18n-title` and `uiText()` key against the dictionary, and the real-browser mirror suite verifies the live swap of a tooltip, dialog prose, and the empty state. Status-bar messages remain English for now, as planned.
- Added a configurable Header column: type any header name in the Columns menu (`x-request-id`, `x-cache`, `etag`, …) and the hidden-by-default Header column binds to it — response headers win, request headers are the fallback, lookups are case-insensitive, and the column sorts and filters through the same pipeline as every other column. The name persists beside the other column preferences and works identically in the mirror tab, whose rows already carry full headers. Both READMEs also corrected the column count (13 → 15; the Operation column had never been added to the list).
- Captured WebSocket conversations now survive HAR export: WS rows keep a bounded structured copy of their frames (live capture and HAR import alike, so an imported conversation re-exports intact), and full HAR exports write it back out as Chrome-shaped `_webSocketMessages` — epoch-second timestamps, opcode 1 text up to the 2 KB capture preview, binary frames as opcode 2 without payload, and every fidelity loss (dropped frames, payload-less binaries, the preview limit) declared on the entry. Sanitized exports treat frames as body-class data: the allowlist keeps them out and a `webSocketFramesOmitted` marker makes the omission visible. SSE rows deliberately never gain the key — it is a Chrome WebSocket-entry extension, and emitting it for SSE would make importers mislabel the row.
- The edit-and-resend dialog now accepts a pasted cURL command: a shell-accurate tokenizer (single/double/$'…' quoting, backslash-newline continuations) and a parser for the common flag subset (-X/-H/-d family/-G/-u/-A/-e/-b/--head/--url) prefill method, URL, headers, and body — Chrome's "Copy as cURL" output imports as-is. Unsupported flags are refused by name instead of guessed, file bodies (`-d @file`) are refused with the reason, browser-handled flags like `--compressed` import with a note, and a pasted Cookie header notes that the browser manages cookies. Both READMEs also corrected a stale claim that the mirror tab's resend is read-only — remote resend shipped earlier.
- Three small power-user features. Row right-click now offers `Only domain …` / `Exclude domain …` quick filters that feed the same multiText rules the Filters popup edits (so its badge counts them and they stay editable there); a second "Only" replaces the first instead of intersecting to zero rows, while exclusions accumulate. The export dialog gained `Export sanitized CSV` — a metadata-only spreadsheet view (numeric duration/size, redacted URL and its domain, never a header or body) honoring the displayed-or-selected scope. And the pop-out mirror tab got a keyboard shortcut, Ctrl/⌘+Shift+M, panel-scoped so it cannot collide with DevTools' own bindings, listed in the `?` dialog and both READMEs.
- Internal quality and responsiveness pass. Clicking away from a large multi-selection no longer freezes the panel: the row-replacement path answered every previously selected row with its own full-table DOM query, which was quadratic, and now builds one id→element map per update. HAR export resolves uncached bodies through a bounded four-worker pool instead of strictly one at a time, so a big export takes seconds rather than minutes while in-flight body memory stays bounded; its failure status now distinguishes a sanitizer fail-closed (report it, retrying cannot help) from a build failure (retry or narrow the scope), still as static text. The live-append frame path swaps its per-frame selector query for a direct sibling walk. Six exported-but-never-called functions (an obsolete highlighter and five helpers whose shipped code paths reimplement them inline) were deleted along with their green-but-misleading tests, and the four near-identical theme/language preference loaders and savers collapsed into one shared, contract-pinned state machine behind the same tested wrappers.
- Hardened the verification and audit toolchain. The mirror's real-browser regression — viewer remote control, host command execution, session adoption, and the pop-out minimize handshake — now lives in the repository as a CDP-driven suite (`tests/mirror-browser.test.js` on a new shared harness) instead of ephemeral session scratchpads; the background worker gained direct unit tests for every response branch; browser suites auto-discover the managed sandbox's Chromium so they can no longer silently skip where CI would run them; `vendor/fflate.js` — the one runtime file this repository does not author — is now sha256-pinned in the package audit so a tampered or silently upgraded vendor file fails `extension:check`; a contract test guarantees every `data-i18n` key resolves to a complete English+Japanese dictionary entry; jest coverage now covers all runtime files explicitly; and `docs/architecture.md` caught up with reality (11 runtime files, 17 panel sections, the 20,000-row retention default, and new sections describing the mirror protocol and the Settings/language architecture).
- Hardened the mirror link against real life, closing five gaps a robustness survey confirmed at line level. A mirror tab that outlives its DevTools session now reattaches automatically: the reopened host briefly probes the scoped port, a surviving tab answers and resyncs, and clicking 🪟 while it is mirroring points at it instead of opening a duplicate. Re-sending from a disconnected mirror tab now reports the failure inside the dialog (keeping the edited request) instead of throwing with the dialog stuck open. The mirror tab no longer offers the local sample capture, whose synthetic row ids would collide with the DevTools session's rows over the port. Theme and language changes now propagate live between the DevTools panel and the mirror tab through `chrome.storage.onChanged` instead of waiting for a reload a DevTools panel only gets by closing. And the command channel grew honest failure bounds: commands time out (30 s; 120 s for import results) instead of hanging their affordance, a transfer exceeding its declared size is refused mid-flight, and a viewer that disconnects mid-transfer no longer leaks its accumulated chunks in the host.
- Added a 🎛️ Settings dialog and Japanese support for explanatory text: the toolbar's Retention and theme buttons merged into one Settings opener whose dialog gathers Language (System / English / 日本語), Theme, and capture retention in framed sections. The language choice localizes explanations and guide dialogs only — control labels deliberately stay English so instructions always match the UI — applies instantly, and persists like the theme (extension storage with a localStorage fallback). The undock explainer was also redesigned from a wall of text into visual cards: a red warning card ("closing DevTools stops capture"), a bordered steps card with a drawn Dock side icon row highlighting the undock icon, and a ✅ one-time-setup summary. The retention limit now reads from the Settings dialog and the status-bar cache tooltip instead of a toolbar label; remote retention control from the mirror tab is unchanged, while Language and Theme there act on the tab itself.
- The mirror tab now explains the docked case itself: when the pop-out reports that DevTools stayed visible (a docked session has no window to minimize), the tab shows a one-time "Keep DevTools open" dialog that warns closing DevTools stops capture and freezes the tab, walks through the one-time undock (⋮ menu → Dock side → separate window) that makes every future pop-out minimize DevTools automatically, and offers "Don't show this again" — a local display flag only, never traffic data. The minimize outcome rides the existing sync heartbeat's control payload, so a session on an older package without the background worker simply never triggers the dialog.

Rows stream in as they are captured, a one-second sync heartbeat reconciles clears, imports, and retention evictions through snapshot resync, and response bodies travel only when a row asks for them. The tab hides the capture-owning controls (pause, clear, import, retention), keeps its rows if DevTools closes, renders initiator entries as plain text where the Sources panel is unreachable, and adds no permissions.

- Fixed pop-out auto-minimize doing nothing for an undocked DevTools window: the worker asked `getLastFocused` with a `windowTypes` filter that API ignores (deprecated since Chrome 46), and by reply time the fresh tab had already stolen focus, so the type check silently failed.
