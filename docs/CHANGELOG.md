# Changelog

All notable changes to Network+ for DevTools. Versions follow [Semantic Versioning](https://semver.org/); `version` is bumped once per release rather than per commit. Published builds are listed under [GitHub Releases](https://github.com/himiyosh/network-plus-extension/releases).

## Unreleased

- Three small power-user features. Row right-click now offers `Only domain …` / `Exclude domain …` quick filters that feed the same multiText rules the Filters popup edits (so its badge counts them and they stay editable there); a second "Only" replaces the first instead of intersecting to zero rows, while exclusions accumulate. The export dialog gained `Export sanitized CSV` — a metadata-only spreadsheet view (numeric duration/size, redacted URL and its domain, never a header or body) honoring the displayed-or-selected scope. And the pop-out mirror tab got a keyboard shortcut, Ctrl/⌘+Shift+M, panel-scoped so it cannot collide with DevTools' own bindings, listed in the `?` dialog and both READMEs.
- Internal quality and responsiveness pass. Clicking away from a large multi-selection no longer freezes the panel: the row-replacement path answered every previously selected row with its own full-table DOM query, which was quadratic, and now builds one id→element map per update. HAR export resolves uncached bodies through a bounded four-worker pool instead of strictly one at a time, so a big export takes seconds rather than minutes while in-flight body memory stays bounded; its failure status now distinguishes a sanitizer fail-closed (report it, retrying cannot help) from a build failure (retry or narrow the scope), still as static text. The live-append frame path swaps its per-frame selector query for a direct sibling walk. Six exported-but-never-called functions (an obsolete highlighter and five helpers whose shipped code paths reimplement them inline) were deleted along with their green-but-misleading tests, and the four near-identical theme/language preference loaders and savers collapsed into one shared, contract-pinned state machine behind the same tested wrappers.
- Hardened the verification and audit toolchain. The mirror's real-browser regression — viewer remote control, host command execution, session adoption, and the pop-out minimize handshake — now lives in the repository as a CDP-driven suite (`tests/mirror-browser.test.js` on a new shared harness) instead of ephemeral session scratchpads; the background worker gained direct unit tests for every response branch; browser suites auto-discover the managed sandbox's Chromium so they can no longer silently skip where CI would run them; `vendor/fflate.js` — the one runtime file this repository does not author — is now sha256-pinned in the package audit so a tampered or silently upgraded vendor file fails `extension:check`; a contract test guarantees every `data-i18n` key resolves to a complete English+Japanese dictionary entry; jest coverage now covers all runtime files explicitly; and `docs/architecture.md` caught up with reality (11 runtime files, 17 panel sections, the 20,000-row retention default, and new sections describing the mirror protocol and the Settings/language architecture).
- Hardened the mirror link against real life, closing five gaps a robustness survey confirmed at line level. A mirror tab that outlives its DevTools session now reattaches automatically: the reopened host briefly probes the scoped port, a surviving tab answers and resyncs, and clicking 🪟 while it is mirroring points at it instead of opening a duplicate. Re-sending from a disconnected mirror tab now reports the failure inside the dialog (keeping the edited request) instead of throwing with the dialog stuck open. The mirror tab no longer offers the local sample capture, whose synthetic row ids would collide with the DevTools session's rows over the port. Theme and language changes now propagate live between the DevTools panel and the mirror tab through `chrome.storage.onChanged` instead of waiting for a reload a DevTools panel only gets by closing. And the command channel grew honest failure bounds: commands time out (30 s; 120 s for import results) instead of hanging their affordance, a transfer exceeding its declared size is refused mid-flight, and a viewer that disconnects mid-transfer no longer leaks its accumulated chunks in the host.
- Added a 🎛️ Settings dialog and Japanese support for explanatory text: the toolbar's Retention and theme buttons merged into one Settings opener whose dialog gathers Language (System / English / 日本語), Theme, and capture retention in framed sections. The language choice localizes explanations and guide dialogs only — control labels deliberately stay English so instructions always match the UI — applies instantly, and persists like the theme (extension storage with a localStorage fallback). The undock explainer was also redesigned from a wall of text into visual cards: a red warning card ("closing DevTools stops capture"), a bordered steps card with a drawn Dock side icon row highlighting the undock icon, and a ✅ one-time-setup summary. The retention limit now reads from the Settings dialog and the status-bar cache tooltip instead of a toolbar label; remote retention control from the mirror tab is unchanged, while Language and Theme there act on the tab itself.
- The mirror tab now explains the docked case itself: when the pop-out reports that DevTools stayed visible (a docked session has no window to minimize), the tab shows a one-time "Keep DevTools open" dialog that warns closing DevTools stops capture and freezes the tab, walks through the one-time undock (⋮ menu → Dock side → separate window) that makes every future pop-out minimize DevTools automatically, and offers "Don't show this again" — a local display flag only, never traffic data. The minimize outcome rides the existing sync heartbeat's control payload, so a session on an older package without the background worker simply never triggers the dialog.
- Recorded the published v1.11.0 release in both submission dossiers: the ZIP was re-downloaded from the public release, its 152202-byte size and SHA-256 digest were verified against the pinned value, and the downloaded file was byte-compared against a fresh local build. The Edge dossier's evidence table gained the matching v1.11.0 row.
- Fixed two dossier defects the observation pass surfaced: the Chrome update-submission step still named the v1.10.0 archive as the file to upload — the one repoint the v1.11.0 cut missed — and the Chrome observed-facts section had carried the same evidence-boundary sentence twice since v1.10.0. The release runbook's repoint step now ends by grepping both dossiers for the previous version string, which catches exactly this class of miss before it is committed.
- Added a pop-out mirror view: the 🪟 toolbar button opens the panel as a regular browser tab that live-mirrors the DevTools session over a `chrome.runtime` port. Rows stream in as they are captured, a one-second sync heartbeat reconciles clears, imports, and retention evictions through snapshot resync, and response bodies travel only when a row asks for them. The tab hides the capture-owning controls (pause, clear, import, retention), keeps its rows if DevTools closes, renders initiator entries as plain text where the Sources panel is unreachable, and adds no permissions.
- Made the `hidden` attribute effective for toolbar buttons: the shared `.topbar button` display rule was silently overriding it, so a control hidden by script still rendered. Caught by the real-browser smoke pass for the mirror view and now pinned by a UI contract test.
- Capture now explicitly survives page navigation: the table has never been cleared on navigation and a contract test pins that, response bodies prefetched before the navigation stay readable, and bodies the browser discarded before retrieval flip to an explicit "navigated away" notice — shown in the Body tab, propagated over the mirror port with its real reason, and counted in the status bar — instead of failing with a timeout later.
- Documented how to open the panel as a browser tab: a step-by-step "Open Network+ in its own browser tab" section in both READMEs, pointing at the 🪟 toolbar button between the theme toggle and the shortcuts button.
- Added a sanitized Markdown copy for bug reports: the row menu's "Copy sanitized Markdown" produces an issue-ready block (method, redacted URL, status, operation, timing), a multi-row selection offers one compact Markdown table, and the format also joins the full-output dialog behind its usual per-action confirmation.
- HAR imports now thread Chrome's `_webSocketMessages` into the same request/response Body panes that live WebSocket capture uses, sorted by time, with binary frames summarized by size and a visible notice when a conversation exceeds the 1,000-message import limit.
- Rewrote both store-listing descriptions around what actually distinguishes the panel — safe sharing by default (sanitized copies including the new Markdown formats, displayed-or-selected export scope), correct charset decoding, side-by-side request diffing, and this cycle's pop-out mirror tab, navigation persistence, opt-in WebSocket capture, and Operation column — while carrying the reviewed retention, sample-guide, and accessibility paragraphs over intact. Edge grew from 3,208 to 4,682 characters and Chrome from 3,378 to 4,852, both inside the validated limits.
- Re-captured the four store screenshots and the README tour GIF against the current panel, so the listing media now shows the color-coded method badges and the export dialog's displayed-or-selected scope choice; `docs/store-assets/inventory.json` and the pinned asset-review date moved to 2026-08-22 together.
- Added edit-and-resend: the row menu re-sends a captured request unchanged, or opens a prefilled dialog (method, URL, headers, body, cookie toggle) first. The composed request is issued by the inspected page itself over the DevTools eval API — cookies, CORS, and the page's security policies apply as usual, browser-managed headers are filtered with that limit stated in the dialog, and the reply arrives as a new captured row. DevTools sessions only; WS rows and the mirror tab are excluded, and the privacy notice records the boundary.
- JWT-shaped header values now decode inline in both Headers panes: each token gains an expandable section with the decoded header and claims, humanized `exp` / `nbf` / `iat` times, and an "expired N min ago" flag, and every section states that the signature is not verified. Display only — sanitized copies keep redacting the raw token, and decoded claims never join copies or exports.
- Fixed pop-out auto-minimize doing nothing for an undocked DevTools window: the worker asked `getLastFocused` with a `windowTypes` filter that API ignores (deprecated since Chrome 46), and by reply time the fresh tab had already stolen focus, so the type check silently failed. The worker now lists devtools-type windows via `getAll` — focus breaks ties, a single window wins even after focus moved, and an ambiguous multi-window case declines rather than guessing — and the pop-out status now states the outcome either way ("the DevTools window is minimized…" / "DevTools stayed put — undock it…"), so a docked no-op explains itself.
- The pop-out mirror tab is now a full remote control, not just a view: its toolbar's pause/resume, clear with undo, retention dialog, HAR/SAZ import, stream-capture toggle, and edit-and-resend all execute in the DevTools session over a new command channel on the mirror port (protocol v2), with the host answering every command and its paused/retention/undo/stream state riding the one-second sync heartbeat back into the tab's buttons. Import files travel as bounded base64 chunks (64 MiB cap) into the exact import pipeline the DevTools file picker uses; remote clicks reuse the host's own controls so undo snapshots and guards behave identically; and a document-level capture interceptor keeps the tab's controls from ever acting locally (same-element listeners fire in registration order, so a per-button interceptor cannot). Only the guided local sample stays DevTools-side.
- Opening the pop-out mirror tab now minimizes an undocked DevTools window automatically, so capture keeps running out of the way (restore it from the taskbar; a docked DevTools is part of the page's window and stays put). This is the package's first background service worker — a single-job, audited one that finds the window by its devtools type through the permissionless `chrome.windows` API, reading no tab URLs or page data — and the package guard now admits exactly that shape while still rejecting every other privileged manifest surface; permissions remain `storage` only.
- Fixed the extension-errors pile-up reported from the pop-out mirror tab: the automatic response-body prefetcher was running in the viewer too, so every live-streamed row queued a body pull over the mirror port — against the tab's bodies-on-demand design — and once the DevTools session closed, the queued fetches failed in batches logged as "automatic response prefetch failed for N requests". The viewer now runs no automatic prefetch (bodies still load on click, and the live-row path tolerates the absent scheduler instead of crashing); a real-browser repro streams 40 rows, disconnects, and pins both the zero-auto-fetch and the zero-error outcome.
- The pop-out mirror tab now teaches the keep-capturing workaround when its DevTools session closes: the disconnect status says capture continues only while DevTools stays open and that an undocked, minimized DevTools window is enough, and both READMEs' pop-out guides document the same undock-and-minimize setup, the batched WS/SSE polling while minimized, and the resync that reopening DevTools triggers.
- Stream capture now also records Server-Sent Events: the opt-in toggle (renamed from "WS capture" to "Stream capture" while both features are unreleased) additionally wraps `EventSource`, threading every message — named events included, once the page listens for them — into the response Body pane as `↓` lines with open/error/close lifecycle marks, an SSE method badge at the same pinned WCAG AA contrast, and the same pause, sample, and navigation discipline as WebSocket capture. The same change fixes a latent WebSocket-capture defect: frames arriving in the same one-second drain batch as their connection were dropped — and the connection then recorded nothing ever after — because a row still queued for the live flush was mistaken for a removed one.
- Extended the manual test checklist with three sections for the features this cycle added — pop-out mirror tab, navigation persistence, and export scope / operation labels / WebSocket capture — since full DevTools-context behavior is exactly what automation here cannot reach.
- Added an Operation column (off by default) that reads GraphQL `operationName` — falling back to the parsed query / mutation / subscription name, batches included — and JSON-RPC `method` out of POST bodies, so API rows can be scanned, sorted, and filtered by what they do; the label also appears in the request Headers pane and travels over the mirror port.
- Added opt-in WebSocket capture with no extra permissions: a status-bar toggle wraps the inspected page's `WebSocket` constructor through the DevTools eval API, records each connection as a WS-badged row, threads sent frames into the request Body pane and received frames plus lifecycle events into the response Body pane (searchable and export-sanitized like any body), reinstalls itself after navigations, and states its limits in the toggle itself — only sockets created while capture is on are seen, and traffic is never altered.
- Colored method badges: known HTTP methods (GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS) now render as tinted pills in the Method column, with every foreground/background pair pinned at WCAG AA contrast in all four theme states; unknown methods keep their plain bold text. Inspired by how Net Logs colors its method column.
- Added a selected-rows export scope: when rows are selected (Ctrl/⌘-click or Shift-click), the export dialog offers "Selected requests only" beside "All displayed requests", each with a live count. The choice applies to sanitized and full exports alike, exported files gain a `-selected` suffix, the selection keeps capture order regardless of the current sort, and "All displayed requests" is re-checked on every open so a leftover selection never silently narrows an export.

Because `pull_request_target` and `issue_comment` resolve the workflow definition from the base repository's default branch, a dedicated workflow that never checks out or executes PR code verifies the exact-head marker using only the checker on the default branch, and publishes the `independent-review` commit status fail-closed. A pull request that rewrites the checker, its tests, or the workflow still cannot change what its own run verifies. Least privilege (`permissions: {}` plus status write), no dependency installation, a pre-verification failure seed, and follow-through on marker posting and deletion are pinned by mutation tests over a step allowlist and step-body digest.
- Red-teamed that pin twice and closed the bypasses found in practice. The first pass found routes that neutralized the gate without changing a single byte of a step body (job-level `container:`, `defaults.run.shell`, job-level `env:` shadowing, a second job, `on:` `paths-ignore`, and top-level `env:` `GH_HOST` / `NODE_OPTIONS`). The second pass found that the region above `on:` entered no digest and that top-level key enumeration was a line regex, so Prettier's canonical `'defaults':` form could swap `run.shell`. Enumeration of top-level keys, job IDs, and job keys plus a job-header digest were added, with a final catch-all digest over the **entire workflow file** so correctness no longer depends on slicing regions with regexes. Both routes are pinned by mutation tests.
- Documented, from measurement, what that boundary does not cover (PR #120). The commit-status namespace is shared across the Actions app, so a workflow inside a PR that declares `permissions: statuses: write` can post the same context, and branch protection cannot distinguish the poster. Unwitting weakening is now mechanically impossible, but deliberate forgery is not prevented. The permanent fix — a check owned by an independently owned GitHub App — remains open under issue #95.
- Resolved high-priority audit recommendations through dependency updates (brace-expansion GHSA-rgw5-rvv9-x895 to 1.1.18/2.1.4/5.0.9; js-yaml GHSA-5p4m-2wfm-xmqj to the 3.15.1 backport, which is inside the `^3.13.1` range declared by `@istanbuljs/load-nyc-config`). With audit clean, the time-boxed exception script `scripts/check-audit-policy.js` was removed as its own policy required, and `audit:strict` is now plain `npm audit --audit-level=high`.
- Bound the independent-review gate to the reviewer UUID configured in repository Actions variables, failing closed before marker evaluation on missing, malformed, or equal reviewer/merger configuration, a mismatched marker, empty implementation-session attribution, or a PR metadata total that changed during collection. Network+-specific markers, a deterministic variable rotation and recovery runbook, and the external trusted-check boundary of issue #95 are now written down.
- Made the independent-review gate read the total commit count from pull request metadata and fail closed before marker evaluation when it disagrees with the collected set of at most 250 commits. Pull requests above 250 commits must be split into several of 250 or fewer and re-run through the review gate.
- Added the exact-head `independent-review` marker gate as the final step of required Node 22/24 CI, requiring agreement between the marker on the first non-empty unfenced line of a GitHub `OWNER` comment, the full reviewer UUID, and the `Copilot-Session` trailer of physical and escaped PR commits.
