# Network+ for DevTools - Product

## Register

product

## Users

Microsoft Edge DevTools で HTTP 通信を調査する Web 開発者、QA エンジニア、サポートエンジニア。
限られたパネル領域で大量のリクエストを扱い、障害原因や性能劣化を短時間で特定する必要がある。

## Product Purpose

標準 Network パネルを補完し、リアルタイムキャプチャ、複合フィルタ、横断検索、詳細比較、
HAR/SAZ 入出力を一つの高密度な作業面に統合する。

成功とは、ユーザーが必要なリクエストと根拠データへ迷わず到達し、安全かつ正確な情報を使って
問題の再現、切り分け、共有を短時間で完了できることである。

## Brand Personality

**正確・効率的・信頼できる。**

専門家向けツールとして落ち着きと明快さを保ち、装飾より操作速度とデータの判読性を優先する。

## Anti-references

- マーケティングサイト風の大きなヒーロー、低密度なカードグリッド、過剰な余白
- 装飾目的の glassmorphism、グラデーション文字、意味のないモーション
- 状態や操作結果が曖昧で、色だけに意味を依存するインターフェース
- Edge DevTools の操作慣習を崩す独自性や、データ表示よりブランド表現を優先する構成

## Design Principles

1. **根拠までの時間を短縮する** - 高頻度操作は少ない手順で完了できるようにする。
2. **密度と明快さを両立する** - 情報量を維持しながら、階層、整列、状態差を明確にする。
3. **ユーザーの操作を尊重する** - 手動スクロールや選択状態を自動処理で上書きしない。
4. **正確性と安全性を既定にする** - ネットワークデータを改変せず、XSS 安全な DOM API で描画する。
5. **DevTools に自然に馴染ませる** - 既存の操作モデルを踏襲しつつ、分析能力と発見可能性を高める。

## Accessibility & Inclusion

- WCAG 2.2 AA を最低ラインとする。
- 主要操作はキーボードのみで完了でき、フォーカス位置と状態変化を視覚的・意味的に示す。
- リクエストが一件もないキャプチャ空状態では、操作対象のないグリッドヘッダーとカラムリサイザーを Tab 順序から外し、サンプルまたはライブリクエストの追加時とフィルタ空状態では即座に復帰させる。
- System、Dark、Light の全テーマでテキストと操作要素のコントラストを確保する。
- 色だけに情報を依存せず、ラベル、形、テキスト、ARIA 状態を併用する。
- モーションを追加する場合は `prefers-reduced-motion` を尊重する。
